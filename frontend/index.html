Understand Chunking Strategies

In RAG (Retrieval-Augmented Generation), chunking is the process of breaking input text into smaller segments. Choosing the right size and technique ensures the LLM receives highly relevant context.

Fixed-Size Chunking

Splits text into chunks of exact character lengths with a specific overlap. Simple and fast, but completely ignores document structure and semantic boundaries.

Advantages

  • Extremely fast computation
  • Predictable token consumption

Disadvantages

  • Breaks sentences/words in half
  • Loss of semantic context

            Document Segmentation Steps

            Step 1
            Detect Document Structure

            Analyze layout properties, line spacings, and formats to parse structural lines.

            Step 2
            Identify Titles & Headings

            Apply structural regular expressions to detect header lines (Markdown headings, numbered sections, QA lines, capitalized title lines).

            Step 3
            Build Section Hierarchy

            Resolve nesting levels (e.g. H1 parent of H2, H2 parent of H3) and build the section structure tree.

            Step 4
            Align Chunks with Boundaries

            Form chunk segments exactly matching heading boundaries, preventing text fragmentation.

            Step 5
            Attach Metadata

            Link level, section order, parent headers, and chunk indexes for rich contextual filtering.

            Step 6
            Generate Final Chunks

            Output final coherent document chunks ready to be stored in the vector database.

            Why Document Chunking is better than Fixed Chunking

            Document Chunking splits text exactly at logical headings, preserving complete contexts. In contrast, fixed chunking cuts lines at arbitrary boundaries, frequently breaking sentences and words.

            ✓ Highly Effective:
            • Research Papers
            • Policy Documents
            • API Documentation
            • Knowledge Bases
            • Legal Contracts
            ✗ Performs Poorly:
            • Plain Text Files
            • OCR Documents
            • Poorly Formatted Files
            • No Headings

            Semantic Concept Lab

            What is an Embedding?

            Embeddings convert human text into numerical representations (vectors) that capture meaning. By placing sentences in a mathematical space, we can measure how close they are in meaning, without relying on exact word matches.

            1 Sentence: "FastAPI is fast"
            2 Embedding Vector: [0.12, -0.45, ..., 0.89]
            3 Similarity Calc: Cosine distance between vectors
            4 Chunk Decision: Split if similarity < threshold

            Fixed-Size vs. Semantic Chunking

            Fixed chunking splits text blindly at a character or token count, which mixes different topics or breaks key sentences. Semantic chunking waits for the topic to shift before starting a new chunk.

            Fixed Chunking
            Chunk 1:
            - AI Introduction
            - AI Applications
            - Stock Market (mixed!)
            Semantic Chunking
            Chunk 1:
            - AI Introduction
            - AI Applications
            Chunk 2:
            - Stock Market (clean split!)

            How Similarity Threshold Affects Output

            The similarity threshold controls how strictly sentences must relate to stay in the same chunk. Adjusting this value alters the chunk size and total count dynamically.

            Threshold = 0.90 Result: Many Small Chunks
            Threshold = 0.50 Result: Balanced Chunks
            Threshold = 0.20 Result: Very Large Chunks

            Best Suitable For

            • ✓ RAG Systems: Keeps full answers together for better model responses.
            • ✓ Knowledge Bases: Organizes company documents logically.
            • ✓ Research Documents: Segments long, complex texts by topic.
            • ✓ Technical Documentation: Groups user guides or code guides cleanly.
            • ✓ Enterprise Search: Ensures search queries retrieve high-precision contexts.

            Reason: Semantic chunking matches how humans search—by topic, not by word counts.

            Less Suitable For

            • ✗ Very Small Documents: If a document is under a few sentences, semantic clustering is redundant and slow.
            • ✗ Real-Time Low-Latency Systems: Encoding embeddings on-the-fly adds significant response delay.
            • ✗ Resource-Constrained Environments: Running deep learning transformers consumes massive RAM/GPU.

            Reason: Simple splitters (like recursive or fixed) are instant and use zero extra server resources.

            Query-Aware Chunking Concept Lab

            Why Query-Aware Is Different

            While both strategies use semantic embeddings, their split boundaries serve completely different purposes:

            Semantic Chunking: Creates topic-based chunks statically, completely independent of any user query. It looks only at topic shifts in the document.
            Query-Aware Chunking: Creates or prioritizes chunks dynamically based directly on the user's search intent, aligning chunk boundaries to capture relevant answers.
            Example Case:
            • Document: "Apples are red. The leave policy allows 20 days off. Python is fast."
            • Query: "How many vacation days do I get?"
            • Query-Aware Split: Extracts "The leave policy allows 20 days off" as the target chunk, ignoring fruit and coding sentences.

            Query-Aware Retrieval Flow

            This diagram outlines how queries guide chunk extraction and boundary refinement:

            1 User Query: Intent check
            2 Query Embedding: Convert to vector
            3 Similarity Scoring: Compare vectors
            4 Relevant Region Detection: Focus target
            5 Chunk Boundary Creation: Split text
            6 RAG Retrieval: Inject into LLM

            Best Practices

            • ✓ Collect User Questions: Gather common inquiries before designing query-aware boundaries to ensure your test query vectors align with real search patterns.
            • ✓ Measure Retrieval Precision: Evaluate performance based on retrieval accuracy and context quality rather than simple chunk counts.
            • ✓ Cache Query Embeddings: Store calculated vector embeddings for frequently searched questions to save on compute resources.

            Common Mistakes

            • ✗ Single Intent Assumption: Assuming that a single query vector is sufficient to represent all diverse user search intents.
            • ✗ Ignoring Synonyms: Neglecting synonymous phrases or colloquial search inputs, causing vector distance mismatches.
            • ✗ Overfitting Boundaries: Slicing document structures around a small, static query dataset, leading to poor generalization for new questions.
